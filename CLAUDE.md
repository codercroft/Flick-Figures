# Flick Figures

Mobile game built in Godot 4 with GDScript.

## Concept

- Turn-based roguelike, portrait orientation, playable entirely with one thumb.
- Top-down tabletop view (no gravity). Little plastic toy figures are flicked (mostly UP the board) at enemy figures. The player can flick in any direction: drag opposite to where you want it to go.
- **Win condition:** knock all of the opponent's figures off the board. A run is 3 acts (branching map, shops, events/minigames, elites, a boss per act), drafting 27 figure types plus relics, powers, equipment, finishes and upgrades. Difficulty: Ascension 0 is flat (4 enemies, no act scaling, no enemy gear); Ascension 1-11 turn harder systems on (the list is data-driven in AscensionConfig).
- STATE.md is the full, code-checked description of what the game does right now; CHANGELOG.md lists what each task changed.

## Rules

- The player's unflicked figures sit "on deck" at the bottom of the board.
- Flicked figures stay where they land.
- The player's flicks pass through their own on-deck figures, but collide with flicked figures.
- Enemies can hit on-deck figures.
- A flicked figure can't be flicked again until all the others have been flicked. Then (default) every remaining figure becomes flickable again right where it stands: there is NO reload step. The old rule (tap one board figure to reload it to the deck) still exists behind `Main.reload_enabled` (@export, off by default, for a future relic).

## UI

- Layout rule: STATUS info (Map and Inventory buttons, act and map row, Ascension level, money) lives in a clean bar at the TOP (`TopBar`, a CanvasLayer, on every screen). Readable content and choices (map, shop, reward, equip, upgrade cards) may use the MIDDLE of the screen. FREQUENT combat actions (power buttons, skip/confirm/leave/back) stay in the BOTTOM half for one-handed reach.
- Everything is built with anchors and containers so it fills any aspect ratio (viewport is always 1080 wide, height varies; tall phones like the Pixel 10 are about 1080x2400). Use `set_anchors_and_offsets_preset(PRESET_FULL_RECT)` (plain `set_anchors_preset` leaves a zero-size box for controls created in code). Respect safe areas: `SafeArea.insets()` (`scripts/safe_area.gd`) gives top/bottom/left/right insets in viewport units (zero on desktop; cutout and gesture bar on Android/iOS); `TopBar.height()` includes the top inset.
- `ScreenFrame` (`scripts/screen_frame.gd`): shared layout of reward/shop/equip/upgrade: `title`, `subtitle`, scrolling `content` (cards, middle), `actions` (`add_action(text, cb)` buttons, bottom), `clear()`.
- `TopBar` (`scripts/top_bar.gd`): a Map button, an Inventory button, the sound button, "Act 2/3  Row 4  A5" (the act, the map row of the node being played or last finished, the Ascension level) and money (the relic icons and the old "i" button are gone). In combat, `main._fit_world()` uses GameFeel's Camera2D (zoom and position, world coordinates unchanged) to centre the board between the top bar and the bottom power bar.
- Map (`scripts/map.gd`, `map_view.gd`, `map_icons.gd`): `MapView` is a tall Control inside a ScrollContainer (full-height, `MIN_ROW_SPACING` 150, scrolls if needed, starts scrolled to your position); only reachable nodes tap (tap-slop so scrolling does not select).
- Overlays: `RunInfo` autoload (`scripts/run_info.gd`, CanvasLayer 100) hosts two overlays opened by the top bar: `RunInfo.open_map()` (the view-only map overlay: `MapMini` with the player's position, Close returns) and `RunInfo.open_inventory(tab, selected)` (the full-screen `InventoryScreen`, `scripts/inventory_screen.gd`); `close_overlay()`, `is_open` (main and minigames ignore touches while open), signal `powers_changed` (main refreshes its power bar). INVENTORY: the roster (`DeckStrip`, deck order, like the combat deck) along the bottom, a details box above it (tap a figure, an item or a relic), and above that three big colored tabs filling the rest: EQUIPMENT (grid of `EquipTile`s: drag one onto a roster figure with Godot's drag and drop (`DeckStrip.drop_enabled`, `item_dropped`) to equip it, the old item goes back to storage (`RunManager.equip`); tap an equipped item's badge on a figure (`item_tapped`) or the Unequip button to store it (`RunManager.unequip`)), POWERS (the slots, each with Discard + a Yes/No confirm, `RunManager.use_power(slot)`; works anywhere, also mid-combat) and RELICS (read-only grid, tap for the description). Outside combat the roster can be reordered by dragging (sets the starting deck order); in combat reordering is locked and equipping is locked unless Costume Change is held (own idle turn only) (`RunManager.combat != null`). A Main menu button is in the Inventory's header. The map screen's old Equipment button is gone (the equip screen scene still exists).
- Export lesson: do not `preload` resources in the `RunManager` autoload that reference RunManager (parse cycle in exports broke the shop on Android). `RunManager.config` is loaded in `_ready()`. The shop logs `[shop]` lines and falls back to a basic stock if empty. `tools/smoke_test.gd` checks pools, scenes and shop offers in an exported pack; CI runs it. Locally: `godot --headless --export-pack "Web" /tmp/x.pck`, then from a directory WITHOUT project.godot: `godot --headless --main-pack /tmp/x.pck -s <repo>/tools/smoke_test.gd`.

- DECK ORDER: `RunManager.deck` (and its parallel `deck_equipment/finish/upgrade`) order = the starting positions on the deck strip in `main._spawn_players`. `RunManager.move_deck_slot(from, to)` reorders all four arrays and autosaves (the order is saved with the run since the save stores the deck arrays in order). `DeckStrip` (`scripts/deck_strip.gd`): the reusable row of `FigureBadge` slots (`reorderable`, `selected`, `slot_pressed`, `reordered`; `describe_slot()` text). Also used for the "which figure?" step in rewards (replace a figure; tap a slot then Replace) and in the shop (slot picker; tap then Confirm).

## Project structure

- `scenes/main.tscn` (main scene): Main (`main.gd`) > Board (`board.gd`), Figures (container), AimLine (`aim_line.gd`), UI (`ui.gd`, a CanvasLayer with the turn label and win/lose panel, both anchored to the bottom half).
- `scenes/figure.tscn`: a bare RigidBody2D with `figure.gd`; collision shape and physics are set up in code. `figure.team` is PLAYER or ENEMY.
- `scripts/main.gd`: spawns figures, handles touch input, runs the turn loop with `await` (`State`: PLAYER_TURN > AIMING > SETTLING > ENEMY_TURN, then back; GAME_OVER on win/lose, tap to restart). All feel tunables are `@export`s on the Main node.
- Aiming: tap a figure to select it (yellow ring), then press and drag ANYWHERE; direction and power come from the drag relative to where that touch started (full power at `max_pull_fraction` = 30% of screen width), and the aim line is drawn from the selected figure. Pressing directly on a figure still selects and aims in one motion. Touches are ignored outside the player's turn (`_input` guard).
- Settling: a figure is "slow" below `stop_speed` and "resting" after `settle_frames` slow frames in a row (then its velocity is zeroed). Abilities that push continuously (Magnet) must skip slow figures (`is_slow()`). `_wait_until_settled()` force-stops everything after `max_settle_time` (6s), shows an orange readout of what is still moving after `settle_debug_after` (5s) and prints it, and a `turn_timeout` watchdog hands control back if a turn ever hangs. Never touch a Figure from a snapshot list without `is_instance_valid` (use `_is_alive`): knocked-off figures are freed after their fade, and a script error inside the turn coroutine silently freezes the turn.
- Turn flow: the sides alternate flicks. The player flicks ONE figure, everything settles, then the enemy side takes `enemy flicks per turn` flicks (default 1), then back to the player. At the start of a player turn, if no figure is flickable, `_make_all_flickable()` re-arms the whole squad in place (or, with `Main.reload_enabled`, the player taps a board figure to reload it to deck first).
- Enemy flicks: for each flick `enemy_ai.choose_flick()` evaluates the best shot of EVERY candidate enemy figure and takes the single best one overall (real attacks outrank repositioning, which outranks passing; if nobody has anything it passes and the turn ends early). With `Main.no_repeat_enemy` (@export, default true) the enemy that flicked last is not a candidate, unless it is the only one that can flick. With 2+ flicks per turn each flick picks the best remaining shot and waits for the board to settle before the next. Creepers (The Wall) still creep after the whole enemy turn, ALL together in one go (every piece launched at the same moment, same distance each, then one settle).
- With more than 1 enemy flick per turn the turn label counts them ("Enemy flicks: 1/3", `ui.show_enemy_turn(text)`, updated as the total grows).
- Enemy flicks per turn lives in the lineup data: `DifficultyConfig.enemy_flicks_per_turn` (one entry per act, default 1 each; elite fights add `elite_extra_flicks`) and `BossData.enemy_flicks_per_turn` (The Wall 1, Sniper Squad 2, Slime 1); `RunManager.enemy_flicks_per_turn` holds the current combat's value and `main.gd` reads it (`_enemy_flicks`). Slime and Skull-o-tron fights (`BossData.flick_per_unit`, `RunManager.enemy_flick_per_unit`): the enemy side flicks once per turn for EACH enemy unit on the table (every slime piece; the core and each Skull Ball), recounted every flick (`Main._enemy_flicks_now()`), capped by `Main.max_enemy_flicks` (4, @export); the counter UI is unchanged.
- Figures have two separate flags: `on_deck` (WHERE it is: collision layers, Magnet, a Mr Potential's Skull wearer) and `flickable` (may be flicked this round; unflickable player figures are drawn greyed out). `launch()` sets `on_deck = false` and `flickable = false`; `return_to_deck()` sets both true again.
- Figures use `continuous_cd = CCD_MODE_CAST_SHAPE`. The old CAST_RAY mode made high-power flicks that start close to another figure lose most of their travel (head-on shot at a figure 20px away moved the target ~830px instead of ~1540); measured with a headless two-figure test.
- Collision layers: 1 `on_deck`, 2 `flicked`, 3 `enemy`, 4 `arena` (walls and pins; every figure's mask includes it). On-deck figures are NOT frozen (enemies can shove them): layer 1, mask 3. Flicked player figures: layer 2, mask 2+3. Enemies: layer 3, mask 1+2+3. So player flicks ignore on-deck figures, but enemies hit them.
- The "table" is `board_rect` merged with `deck_rect` (Board node exports). Any figure (either team, on deck or not) whose center leaves the table is knocked off.

## Arenas

- Each combat uses an `ArenaData` layout (`scripts/arena_data.gd`, files in `resources/arenas/`, pool = `RunConfig.arenas`). `RunManager.arena` is picked in `_build_lineup()`: random, never the same twice in a row, and only `creeper_safe` ones when a creeping boss (The Wall) is in the fight. `Arena` (`scripts/arena.gd`, node under Main) builds it; `main.gd` calls `arena.build(RunManager.arena, board.board_rect)` and shows the layout's name for ~2s (`ui.show_arena_name`).
- A layout is lists of `ArenaWall` (rotated rectangle, solid and bouncy), `ArenaPin` (small round bumper that kicks figures `pin_kick` x faster) and `ArenaPatch` (rectangle, not solid: SLOW adds damping, BOOST pushes in `direction_degrees` (`boost_acceleration` on the Arena node, default 470, was 1400: it was far too strong), TURN rotates a moving figure's velocity left or right, speed kept). All positions are in board space: (0,0) is the board's top-left, board is 900x1000, enemies at the top. Keep everything inside the board (the deck strip below must stay clear; `get_warnings()` flags it) and away from enemy spawn points (4-6 enemies at y=160/280, snipers, The Wall at y=160).
- Patches only act on figures that are moving (not `is_slow()`), so they never keep a resting figure moving. Strengths are exports on the Arena node (`slow_damping`, `boost_acceleration`, `turn_rate_degrees`, `wall_bounce`, `pin_kick`...), with a per-patch `strength` multiplier. Layouts: Open Field, Corner Posts, Open Corners, Side Rails, Divider, The Funnel, Pinball, Mud Flats, Speedway, Whirlpool, Crosswinds. To add one: duplicate a `.tres`, edit it, add it to `run_config.tres`.
- Boost/crosswind patches stay away from the side edges (`ArenaData.BOOST_SIDE_MARGIN` 150 px, `get_warnings()` flags violations; Crosswinds is 440 wide and centred, Speedway's lanes are at x 270 and 630) so they can't push figures straight off.
- The enemy AI's shape casts already include the arena layer: shots blocked by a wall or pin are skipped, and it won't count on a wall-blocked edge for a knock-off. With floor effects on the board it follows shots step by step (see Floor awareness below).

## Enemy AI

- `scripts/enemy_ai.gd` (`EnemyAI` node under Main). `choose_flick()` runs `_best_shot_for()` for each candidate enemy (see Enemy flicks above) and that tries candidate shots (every player figure x angle offsets x power levels; speeds are fractions of `reference_speed` x the figure's flick power), and uses `PhysicsDirectSpaceState2D.cast_motion` to find the first figure each would hit (figures already touching the shooter count as hit at distance 0).
- Scoring: `_predict_collision()` does elastic-collision maths along the line of centers (masses, Godot's summed-and-capped bounce, knockback multipliers) to get both figures' velocities right after impact, and `_leave_chance()` turns "slide distance vs distance to the table edge" into a 0-1 chance of going off (ramping from 70% to 120% of the way). Hit on a player figure = `hit_player_bonus` + `kill_bonus` x chance the target is knocked off + `edge_bonus` x how far it is pushed toward the edge; minus `self_knock_off_penalty` x chance the SHOOTER leaves the table (default 300, more than a hit + kill + edge, so a self-knockoff outweighs the kill), minus the same penalty x chance of missing (aim error) x chance the shooter then slides off, minus `overpower_penalty` x power (so the lowest power that still knocks the target off wins). Hitting an ally first is penalized unless the ally is lined up with a player figure behind it. If no attack scores above `min_attack_score` it makes a small safe repositioning flick, or passes. Not modelled: ability side effects such as Crazy Man's bounce boost. Repositioning (`_choose_reposition`): an enemy within `reposition_edge_margin` of the table edge accepts any 180px flick that ends clearly farther from the edge (and inside the table), and if boxed in it makes a gentle flick toward the middle instead of passing (it used to pass because every shot had to END inside the safe area).
- Floor awareness: `_prepare()` (start of every `choose_flick`) reads the arena: `_floor_on` = patches, Juicer trail pieces, magnet zones or Magnet figures exist (`Arena.has_floor_effects()`, `has_bending_floor()`); `_pull_sources` = figures whose ability `has_path_pull` (Magnet). When a shot's straight path comes near something that matters (`_path_affected`, `Arena.floor_near_segment`), `_simulate_flight()` follows it in `sim_step` (0.08 s) steps using `Arena.predict_floor_velocity()` (the same maths as the real slow/boost/turn patches, trails and magnet zones), Magnet pull (`FigureAbility.get_path_pull`) and exponential damping, and `_first_hit_along()` shape-casts the path in ~100px chords; the hit carries the shooter's position and velocity at contact, which `_predict_collision` uses. `_slide_ratio` (knock-off and edge-push chances) also follows the slide when the floor is near (secondary slides such as explosion pushes use the cheap formula, `_fast_slides`) and is cached per decision. Temporary pins and bricks are real bodies, so the casts already see them. Checked: simulated end points match the real slide on Crosswinds and Mud Flats within ~10%. `think_budget_ms` (700) skips the not-yet-examined enemies if choosing takes too long on a slow phone.
- Ability awareness (hooks on `FigureAbility`, all AI-only hints): `get_ai_blast()` (Bombo `when: hit`, Sneaky Bomber `stop`), `has_path_pull/get_path_pull` (Magnet), `get_flick_bounce` and `cancels_rebound` (Pusher: no bounce, no rebound, edge pushes worth `shove_edge_multiplier`). `_blast_value()` scores an explosion: each player figure pushed scores like a hit (`blast_hit_bonus`, knock-off, edge), pushed allies count against it. Combos in `_score_attack`: Bombo adds the blast at the contact point (so it aims at clusters); hitting any ally adds `_ally_chain_value` (the ally's predicted flight is cast and, if it runs into a player figure, scored like that hit, so a a bonk into a Mr Potential's Skull wearer, which takes double knockback from teammates, is a strong chain); `_best_free_blast` makes a Sneaky Bomber stop `free_blast_gap` short of player figures or in the middle of the group on a clear path. Wide angles (`wide_angle_offsets_degrees`) are tried whenever the floor can bend a path, so Magnet curves work as bank shots. Crazy Man aura: enemies reluctant to leave it (`aura_leave_penalty`), repositioning into it gets `aura_stay_bonus`.
- Search depth per tier (`search_depth_regular/elite/boss` 1/2/3, `combo_weight_*` 1/1.5/2): tier = boss fights 3, elite fights or elite-flagged enemies 2, otherwise 1. Depth 2 adds `fine_angle_offsets_degrees` and `fine_power_levels`; depth 3 adds `wide_angle_offsets_degrees` and `extra_power_levels`; the Pinhead pin grid gets finer with depth. The combo weight multiplies blast, chain and bank bonuses.
- Aim error comes from `FigureData.accuracy` (1 = perfect) scaled by the AI's `max_aim_error_degrees`. Power levels, scores and distances are all exports on the EnemyAI node; `debug_draw_shots` draws each enemy's chosen shot (red attack, orange via ally, yellow reposition).
- Wrapping figures (Ghost, Wings; hook `FigureAbility.get_wrap_count(figure)`): on a FREE flight (a miss, or a reposition) the AI follows the straight line, lets the figure wrap to the opposite edge up to its wrap count (`_simulate_wraps`) and only counts the last leg as a self-knockoff risk (`_flight_leave_chance`, `_flight_end`). After a real hit the figure has touched something, so it cannot wrap and the normal self-knockoff prediction stays. Reposition flicks may also end on the far side of a wrap.
- Prediction assumes linear damping: speed falls by `damp * distance`, so slide distance = (speed - stop_speed) / damp.

## Figures (data-driven)

- `scripts/figure_data.gd` (`FigureData` Resource): display_name, color, radius, mass, bounce, damping_multiplier, flick_power_multiplier, knockback_taken_multiplier, and an `ability` slot. Figures are `.tres` files in `resources/figures/`: Pusher, Duwall, Powerhouse, Bombo (player) and Grunt (enemy). Make a new figure by duplicating one in the editor.
- EXPLOSION RULE (`Figure.blast_immune(victim, source_team)`; used by `Figure.blast`, `Implosion` and the enemy AI's `_blast_value`): explosions and implosions set off by the PLAYER's side (figures, Blastoid shots, Land Miner mines, Short Fuse/Magnet implosions, the Bomb Drop power via `blast(..., source_team)`) never push ANY player figure (on deck or on the board). Enemy explosions push EVERYONE, their own side included (the Firecracker's team immunity is gone with the figure). Immune figures still get `on_exploded` (Bombo chains). The AI's `_blast_value` counts pushed allies against a blast.
- Every explosion's push is scaled by ONE shared export, `RunConfig.explosion_force_multiplier` (1.3), applied in `Figure.blast()` (so Bombo, Sneaky Bomber, Land Miner mines, Short Fuse and Bomb Drop all use it).
- `Figure.explode()` now calls the static `Figure.blast(tree, center, radius, force, source, spared)` (also used by the Bomb Drop power).
- Which figures fight comes from the `RunManager` autoload (the player's deck and the current combat's enemy lineup), not from Main exports. Main's `figure_damping` is the base damping that each figure's `damping_multiplier` scales.
- Abilities: `scripts/abilities/figure_ability.gd` (`FigureAbility` Resource) is the base class with no-op hooks `on_flicked`, `on_hit`, `on_stopped`, `on_exploded`. Subclass it (see `bombo_ability.gd`) and pick it in the FigureData's `ability` slot; ability tunables are `@export`s on the subclass. Each figure runs its own duplicate of the ability, so per-figure state is safe. To add a new event, call it from `figure.gd` (hooks are called deferred from physics callbacks).
- `Figure.explode(radius, force, spared)` pushes nearby figures (except `spared`) (linear falloff) and fires `on_exploded` on them. `take_knockback()` and the collision handling in `_integrate_forces` apply `knockback_taken_multiplier`.
- Bombo explodes on its first hit after each flick (resets on flick), and survives; its blast radius is 200 (about 60% of the original 320) and force 900 (was 2000; NOTE `bombo.tres` overrides the script default, so change both there).

Enemy AI: the pin is the Pinhead's whole action. `EnemyAI._best_pin_setup` tries a grid of pin spots and scores each by the best bank shot (`_bank_shot_via`: mirror-bounce contact point, both legs checked with `_first_hit(..., from)`, lowest power that still arrives with `bank_min_hit_speed`, minus `bank_shot_penalty`) that ANOTHER enemy figure could take off it, times `pin_setup_factor` (0.8), and uses it only if that beats the Pinhead's own best shot (`choose_flick` returns `pin_only`; `main._run_enemy_turn` places it and counts it as that enemy's flick). Every enemy also checks bank shots off the enemy side's existing temp pins (`Arena.temp_pins_of`).
    - Juicer (JU, `juicer_ability.gd`): `on_physics_process` drops a `TrailSegment` (via `Arena.add_trail_segment`) every `segment_spacing` px while moving faster than `min_trail_speed`. Each piece pushes MOVING OPPOSING figures (never its own team; not on deck) that are inside it BACK the way Juicer came from (the trail points opposite to its travel) with `boost_acceleration` 150 (arena boost patches: 470), capped by `boost_max_speed`; pieces fade over `trail_rounds` (3) rounds (`Arena.tick_round`) and each Juicer keeps at most `max_segments` (30). SPLASH (`on_impact`): when Juicer hits an OPPOSING figure at >= `splash_min_speed` it also drops `splash_count` (6) trail pieces in a ring `splash_distance` (75 px) around the impact point, each pushing opposing figures outward from it (same fade as the trail). JUICE DOUSE: an opposing figure touching any piece (`Arena._apply_trail_piece`, body within `segment_radius` + its radius, moving or not, not on deck) gets `Figure.douse(douse_rounds 2, douse_knockback 1.2, juice=true)` (@exports on the ability): the shared Doused status, refreshed on contact, never stacking; `Figure.douse` ignores a weaker multiplier while a stronger Douse is active, so an Alchemist's 1.5 wins and replaces the juice version (`doused_juice` picks the lighter green tint in `_draw_doused`). AI: `juice_path_penalty` per player juice piece on a shot path (`Arena.juice_pieces_on_path`, max 3) and `juice_push_bonus` per own juice piece the target's predicted slide crosses (max 3). The enemy AI follows trails in `_simulate_flight` and ignores its own team's (`predict_floor_velocity(..., team)`, `floor_near_segment(..., team)`; pieces store their `team`).
    - New icons PIN and DROPLET in `figure_icons.gd`. Arena visuals (zones, trail pieces) must use z_index 0: the Board is drawn first and z -1 hid them under it.
  - New hooks on `FigureAbility`: `get_explosion_multiplier(figure, source)` (explosions go through `Figure.take_explosion()`), `get_flicks_per_turn(figure)`, `on_left_table(figure, table)`. Helpers on Figure: `nudge(velocity_change)`, `show_popup(text)`.
- Extra ability hooks beyond the four events: `on_impact(figure, other, speed, point)` (like `on_hit` but with the relative impact speed), `on_physics_process(figure, delta)` (continuous effects) and the modifier `get_knockback_multiplier(figure, source)` (applied to collisions and `take_knockback`).
- `resources/figure_registry.tres` (`FigureRegistry`): `grunts` (just the plain Grunt), `draftable` (reward pool and shop stock; every non-grunt figure), `economy` (the "economy" tag: Cha-ching, Piggy Bank and any future economy figures; they can be drafted or sold but `random_non_grunts()` never puts them in an enemy lineup, so add new economy figures to this list), `explosive` (the "explosive" tag: Bombo, Sneaky Bomber, Blastoid, Aggro-bom; `is_explosive()`; add new exploding figures here so Bombo's Shrapnel upgrade can set them off), and `bosses` (`BossData`: The Wall, Sniper Squad, Slime, Skull-o-tron), plus `random_grunt()`, `random_non_grunts(count)`, `random_draftable(count)` and `random_boss()`. A figure can be in more than one list.

## Run structure

- ASCENSION (`AscensionConfig`, `resources/ascension_config.tres`, `RunConfig.ascension`; every number is an export there): `RunManager.ascension` (0-10, set by `start_new_run(level)`, `asc(n)` = level >= n; each level includes the lower ones). ASCENSION 0 IS FLAT: 4 enemies per regular combat in every act (`base_enemies_per_combat`; hand-made encounters are topped up with Grunts / trimmed to it, `_enemy_count()`, `_trim_lineup`), NO act stat multiplier (`enemy_scale` returns 1s; bosses too), no random enemy finishes / equipment / upgrades (encounter-forced gear such as The Setup's Skull and Mirror Match's copies stay), elites get no stat boost, no guaranteed gear and no enemy relic. Everything else (encounter and elite pools, AI depth, boss rules, the player reward curve, event penalties) is unchanged. The removed systems stay in the code and are switched on by levels: 1 Geared Enemies (`ascension.gear` = the EnemyGearConfig rates; elites/bosses roll one act later), 2 Harsher Events (minigame loss = extra Grunt AND gear), 3 Rising Threat (`DifficultyConfig` multipliers incl. bosses, and 4/5/6 enemies), 4 Leaner Economy (shop prices x1.5, rounded up, in `enter_node`; no Cha-ching nerf any more), 5 Hardened Elites (`EliteConfig` boost and guaranteed gear), 6 Fewer Offers (figure choices capped at 2 in `offer_rewards`, chance drops x0.5 in `_roll_drop`), 7 Elite Relics (`_pick_enemy_relics`, 1 per elite in every act), 8 Boss Upgrades (`_apply_boss_ascension`: through per-enemy boost dictionaries, `ability_values` / `creep`, extra snipers, Trangle 3 flicks, `boss_summons` swaps the Mad Creator's Grunt space for a Bombo), 9 Bigger Squads (+1 enemy in regular combats), 10 Double Boss (`combat_won` -> `_start_second_boss`: after the last act's boss the other act 3 boss is built and `main` reloads the scene with no rewards; `in_second_boss`). PROGRESS: `AscensionProgress` (static, `user://ascension.json`) keeps the highest unlocked level; `end_run(true)` unlocks the next when the run was won at the highest unlocked level (`newly_unlocked_level`, shown on the win screen). The main menu's New Run opens an Ascension selector (unlocked levels, description and a summary of everything that stacks: `AscensionConfig.summary`). The level is shown in the top bar ("A3"), saved with the run (`RunSave`), recorded in run history (`ascension`) with per-level win stats (`RunHistory.ascension_stats()`, shown in the Run History screen).

- A run is `RunConfig.acts` (3) acts. Each act has its own branching map ending in its own boss; money, deck, powers, relics, equipment and upgrades carry across acts. `scripts/run_manager.gd` is the `RunManager` autoload: `act`, `act_bosses` (different bosses picked at run start with `registry.random_bosses(acts)`, no repeats), `map` (`ActMap`), `current_node` (last finished node id, -1 at the start of an act), `node` (the node being played), the lineup (`enemies`, `enemy_elite`, `enemy_flicks_per_turn`), `reward_steps`, plus deck/money/powers/relics/equipment. It never touches scenes.
- Flow: `scenes/main_menu.tscn` is the first scene; `scenes/map.tscn` shows the act map. Tap a glowing next stop: `RunManager.enter_node(id)` then the scene by type: combat/elite/boss -> `main.tscn`, shop -> `shop.tscn` (fresh stock each visit), treasure -> `reward.tscn`. Winning a combat: `main._end_game` awards income, `RunManager.combat_won()` builds `reward_steps`, then `reward.tscn` runs them; when the steps are done `RunManager.finish_rewards()` finishes the node (or, after a boss, starts the next act with a new map) and the map is shown. Beating the LAST act's boss shows the run-complete panel (tap to restart) instead of rewards. Losing shows the result panel (tap restarts). `main.tscn` is one combat and is rebuilt fresh each time.
- Map generation (`scripts/map/act_map.gd`, `map_node.gd`; tunables in `resources/map_config.tres` = `MapConfig`): `columns` (6) x `lanes` (4) grid, at most one lane missing per column, each node links to 2-3 nodes of the next column (edge-lane and missing-lane nodes can have 1; last column all link to the boss), crossing lines avoided where possible. Types (`MapNode.Type`): COMBAT, ELITE, SHOP, TREASURE, BOSS. The CHEST ROW: the whole column `chest_column` (2, the middle) is TREASURE nodes on every act's map, so every path passes exactly one chest (it always gives a relic). SHOPS: 1-3 per act (`MapConfig.shop_count_weights` [1, 2, 1] = about 2 on average), only from `shop_from_column` (2 = the 3rd row) on, never in the chest row, at most one per row, at a random node of the row; there is NO guarantee that every path passes a shop (the old cover rule was dropped). Elites only from `elite_from_column` (3) on, never forced (`_make_elites_optional`), at least one per act, column 0 is all combat. Verified over 2000 generated maps: every path has exactly one chest, shops obey the row rules (average 2.02), elites avoidable. `map.gd` draws it (placeholder icons: crossed lines combat, star elite, $ shop, chest treasure, boss label; reachable nodes pulse, taps on them go there).
- EVENTS: map node type `MapNode.Type.EVENT` (purple "?" icon). 1-3 per act (`MapConfig.event_count_weights` [1, 2, 1], usually 2), same rules as shops (from `event_from_column` = 3rd row, never the chest row, one per row), placed on plain combat nodes. `EventData` (`scripts/events/event_data.gd`: name, description, `scene`) lives in `RunConfig.event_pool`; `RunManager._pick_event()` takes one not seen this run (`used_events`), and the map opens its scene. TO ADD AN EVENT: a script extending `EventScreen` (`scripts/events/event_screen.gd`: a `frame` (ScreenFrame), `start()` to build the first screen, `add_card()`, `show_result(text)`, `leave()` which finishes the node and returns to the map), a scene under `scenes/events/` with it as root, an `EventData` in `resources/events/`, and an entry in the pool. THE TRADER (`trader_event.gd`, `@export` high_trade_cost 6): Low = give a power or an unequipped equipment item, get a different random power or equipment item; Medium = give a figure, get a random Common/Uncommon figure that is shown first (`replace_figure`); High = pay $6 and give 1 figure (get an Uncommon) or 2 figures (get a Rare), the new figure comes with one fitting finish, upgrade or equipment (`GearRules`); the pick is a toggle list. Trades you cannot do are shown disabled; the deck never drops below one figure (`RunManager.remove_deck_slot`). MINIGAME PENALTY: `RunManager.minigame_penalty` (set by a future event or minigame): the next combat entered gets +1 Grunt in a free spot or one enemy gets a compatible finish/upgrade/equipment (never an extra Grunt in boss fights), then the flag clears (`_apply_minigame_penalty`), the combat banner says what changed (`penalty_text`), and the map shows "! The next fight will be harder" while it is set.
- MINIGAMES (four events in the pool: Bocce, Curling, Bowling, Mini-Golf; each its own scene `scenes/events/*.tscn` with an `EventData` in `resources/events/`). `Minigame` (`scripts/events/minigame.gd`, Node2D) is the base: an open table (`board_rect`, same 900x1000 as combat, centred by a Camera2D like `_fit_world`), real `Figure`s (same flick maths: drag anywhere opposite the direction, `max_flick_force`, `max_pull_fraction`), the aim line, a `TopBar`, a status label at the bottom and a result panel (`show_result`) with Continue. Any figure whose center leaves the table falls (`on_fell`). Subclasses override `_run()` (an `await` loop using `request_flick(figure, prompt)` and `wait_until_settled()`) and `_draw_table()`. Player figures are spawned "on deck" and launched (layer 2); the AI's and props (jack, pins) are ENEMY team (layer 3) so every body hits every other. Rewards come from `MinigameConfig` (`scripts/minigame_config.gd`, `resources/minigame_config.tres`, `RunConfig.minigames`): `win_money` (6), `win_item_kinds` (power/equipment/finish), `ai_accuracy` (0.6, about 8 degrees of error), `ai_power_error`, `ai_think_time`, `golf_ai_accuracy` (0.7) / `golf_ai_power_error`. `give_reward(money, kind)` pays at once and sets `RunManager.reward_steps` plus `event_reward_text`; with an item, Continue goes through `reward.tscn` (which shows the text for EVENT nodes), otherwise straight back to the map (`finish_node`).
  - `VersusMinigame` (`versus_minigame.gd`) = the Bocce/Curling rules: a coin flip (shown for `coin_flip_seconds`) decides who flicks first, then alternate (`stones_each` Grunts each, blue = you, orange = opponent). The Grunts are `stone_mass_multiplier` (3.5) times heavier with the flick power raised by the same factor (same travel as a normal Grunt) and `stone_bounce` 0.1 (a hit stone takes about half the hitter's speed: equal masses alone would still pass on almost all of it; the jack stays light). After the last one settles the Grunt nearest `_goal()` wins: win = money + one random item, loss = `RunManager.minigame_penalty = true` (result panel says so), tie = nothing. The result draws distance lines from every Grunt to the goal (winner gold). The opponent is `MinigameAI` (`minigame_ai.gd`): it tries aim points (the goal and every other Grunt) x angle offsets x power levels (`power_step` 0.02), predicts each shot with the combat AI's helpers (an `EnemyAI` child: `_first_hit` shape cast, `_predict_collision`, `_travel_distance`), scores the predicted end positions with `_score_outcome` (how much closer its best Grunt is than yours; losing a Grunt off the table is bad) and flicks the best one with aim and power error.
  - Bocce (`bocce_minigame.gd`): the jack (white, radius 24, mass 0.4) is really flicked from the bottom to a random spot near the middle (`jack_spread`), 3 Grunts each, the opponent flicks down from the top; Grunts can shove the jack and the goal follows it; a knocked-off jack is put back inside the edge. Curling (`curling_minigame.gd`): ring target near the top (`target_distance_from_top`, `ring_radii`), 2 Banana Peel Grunts each (`banana_peel` export, damping x0.5 so they slide ~2x as far: a light flick goes far, a hard one leaves the table), both flick from the bottom.
  - Bowling (`bowling_minigame.gd`, vs the AI): 10 white pins (radius 28, mass 0.45) in a 4-3-2-1 triangle at the top. `rounds` (3): in each you flick the ball twice, the pins reset, the AI flicks twice, the pins reset again. The ball is a Grunt `ball_mass_multiplier` (1.6) heavier with `ball_flick_power` (0.8): launch speed 2400 x 0.8 / 1.6 = ~1200 px/s (a full pull rolls ~790 px), removed after each flick. A pin is "down" (sticky within a turn) once it moves more than `moved_threshold` (30 px) or leaves the table; knocked-over spots are ringed in red. A scoreboard under the top bar shows each round's pins for both sides and the totals. Higher total wins, a TIE GOES TO THE PLAYER; win/loss use `conclude_contest` (money + random item / penalty flag) like Bocce and Curling. The AI uses `MinigameAI` (aim points = every standing pin and their centroid) with `_score_shot`: value for the pin it hits, the pins that pin's predicted slide passes within `ai_chain_reach`, and the pins the ball sweeps afterwards (only first collisions are predicted).
  - Mini-Golf (`mini_golf_minigame.gd`, scene `scenes/events/mini_golf.tscn`): a random `GolfCourse` (`golf_course.gd`: `layout` = a normal `ArenaData` built by the shared `Arena` node, plus `tee` and `hole` in board space; files in `resources/golf/`, listed in the scene's `courses` export). Layouts have their own outer walls (36 px frame) and use walls, pins, SLOW (rough/sand), BOOST (ramp) and TURN patches: Serpentine (two bends, sand trap, pin), Pinball Alley (boost ramp, bumpers, funnel walls, rough around the hole), The Hook (a wall splits the course, sand, a turn patch). You and the AI each have ONE ball (radius 24, mass 0.6, `ball_power` 0.5) starting side by side on the tee; you stroke first, then alternate, up to `max_strokes` (6) each; the balls collide. Every physics frame a ball whose center is within `hole_radius` (36) of the hole and slower than `capture_speed` (450) drops in (`_sink`): the first ball in wins, even if the other side's stroke knocked it in. With no sink after 6 each, the nearer ball wins (distance lines drawn), a tie is a draw. A ball that somehow leaves the course goes back to where it last rested. Win/loss/draw use `Minigame.conclude_contest` (also used by Bocce and Curling). The opponent (`golf_ai.gd`) searches strokes (directions every 6 degrees x 8 powers, then a fine search around the best 4, within `think_budget_ms`) in `GolfSim` (`golf_sim.gd`), a small stand-alone ball simulation: damping, bounces off the walls (rotated rectangles) and pins (kick 1.3), the Arena's `predict_floor_velocity` for patches, the hole's capture rule, the player's ball as a fixed obstacle. So bank shots come out naturally; it then adds aim and power error from `golf_ai_accuracy`. Checked: the simulated end point matches the real ball within ~10% and a simulated sink is a real sink. To add a course: generate/duplicate a `resources/golf/*.tres` (keep the outer frame, tee and hole clear of walls) and add it to the scene's `courses`.
  - To add a minigame: a script extending `Minigame` (or `VersusMinigame`), a scene with it as root, an `EventData`, an entry in `event_pool`. Test headless by driving `_flick_figure` and `player_flicked` from a `-s` script (see how a minigame ends via `_finished`).
- Lineups (`RunManager._build_lineup()`): enemies per combat: 4 in every act in the base game (`DifficultyConfig.enemies_per_combat` 4, 5, 6 only from Ascension 3). Within an act the grunts ramp to non-grunts by the node's column (all grunts at column 0, all non-grunts at the last column; never economy figures). Elite fights: at least `elite_figures_max` non-grunts, 1-2 of them "elite" (extra stat multipliers, gold ring), +`elite_extra_flicks` enemy flick per turn (the elite money bonus is in RewardConfig).
- REGULAR COMBATS use hand-made encounters (except the FIRST combat of a run, `RunManager.first_combat_played`: always just the act's 4 Grunts on a random arena layout; the pool starts from the second combat): `RunConfig.regular_encounters` (files in `resources/encounters/regular/` plus Well-Rounded Squad and Fireworks in `resources/encounters/`; 13 in all: 5 in act 1, 5 in act 2, 3 in act 3; the elite pool `elite_encounters` stays separate). `RunManager._pick_regular_encounter()` picks one available in the act that the run has not played (`used_encounters`; when all are used they become available again). `EncounterData` adds `arena` (its own layout, null = random; `RunManager.encounter_arena`, used by `_pick_arena`), `fill_with_grunts` (tops the lineup up to the act's 4/5/6 with Grunts in the free spot farthest from everything else and clear of walls: `_fill_with_grunts`, `ArenaData.blocks_circle`) and the Mirror Match fields (`mirror_deck`, `mirror_*_multiplier`: one enemy per slot cycling through the deck's figure types, economy ones become Grunts). `EncounterEnemy.positions` are board-space start spots (`RunManager.enemy_positions`, Vector2.INF = default row; `main._spawn_enemies` uses them). The encounter name is shown in gold at the start of combat. Act 1: Bodyguards (Side Rails), Bent Lane (Open Field), Glass Cannons (Pinball), Pushover (Corner Posts). Act 2: Tinderbox (Funnel), Ghost Patrol (Open Field), The Setup (Divider, a Grunt wearing Mr Potential's Skull), Sticky Situation (Mud Flats). Act 3: Fortress (new `fortress.tres`: walls along the edges' middles and two bunkers, corners open), Speed Trap (Speedway), Demolition Crew (Pinball). DESIGN PRINCIPLE: each encounter should pose an interesting question or puzzle with several valid ways to solve it (go around, bank it, shove one figure into another, use an ability), not just one hard counter. Checked headless: every encounter fits its arena (inside the board, no wall or figure overlaps) and fills to the act's count.
- Named encounters: `EncounterData` (`scripts/encounter_data.gd`: `display_name`, `enemies: Array[EncounterEnemy]`, `enemy_flicks_per_turn`, `acts` (1-based list of acts it can appear in)) with `EncounterEnemy` (`scripts/encounter_enemy.gd`: `figure`, `count`, optional boosts `mass_multiplier`, `flick_power_multiplier`, `accuracy_multiplier`, `bounce_bonus`, `ability_strength`). Files in `resources/encounters/`; the elite pool is `RunConfig.elite_encounters`. An elite node picks a random encounter available in the current act (`RunManager._pick_encounter()`); with an empty pool it falls back to the old random elite lineup. The encounter's boosts are stored per enemy in `RunManager.enemy_boosts` and stack on top of the act multipliers in `enemy_scale(i)` (so encounters still scale with the act); `bounce_bonus` and `ability_strength` travel in the same stat-scale dictionary (`bounce`, `ability`) that `Figure.setup` reads. Encounter enemies are not flagged `enemy_elite` (no extra generic multiplier, no gold ring); the encounter name is shown by `ui.show_banner([...])` at the start of combat (gold, then the arena name). Elites (all of them, including random ones) still pay `elite_extra_money` and give the elite rewards.
- ELITES BY ACT (`RunConfig.elite_encounters`, each `EncounterData.acts`; Well-Rounded Squad is now a regular Act 1 encounter and Fireworks a regular Act 2 one, both `fill_with_grunts`). Act 1: Bumper Duo (2 boosted Bumpers), Big Brother (one Duwall at `size_multiplier` 1.5 / `mass_multiplier` 1.5 with `ability_values {"shell_strength": 16000}` in front of 2 Grunts), Shield Wall (3 Shieldon Oopers spread across the enemy side + 1 Grunt), Pinball Wizard (Crazy Man with 2 Speedos inside his 300px aura, always on `corner_posts.tres`). Act 2: Swarm (8 Swarmlings, 3 flicks), Banshee (5 Ghosts, Open Field), Powder Keg (Land Miner + Aggro-bom + 2 Bombos packed so their blasts chain), Glue Gang (Glue Guy with the Goo Chain upgrade + 2 Splitters), Juice Bar (Juicer + 2 Speedos + Bummer). Act 3: Mirror Match (from the player's deck, see below), The Collector (Eater at size/mass x1.3 with `ability_values {"feeds_on_allies": true}` + 4 Grunts near it), Siege (Engineer behind 2 Shieldons and a Duwall on `fortress.tres`, turret up before the first flick via `Main._place_opening_turrets`), Bloodbath (2 Bloodlusters + Alchemist). New `EncounterEnemy` fields: `finish`, `upgrade` (forced on every copy), `size_multiplier` (radius, read as `stat_scale.size` in `Figure.setup`) and `ability_values` (exact ability properties by name, `stat_scale.ability_values`). Mirror Match copies each deck slot's equipment / finish / upgrade onto the matching enemy (economy and player-only items skipped).
- ELITE SCALING (the stat boost and guaranteed gear only from Ascension 5, the enemy relic from Ascension 7; `resources/elite_config.tres`, `EliteConfig`, one entry per act): act 1 elites get a small stat boost (`boost_mass/power/accuracy` 1.05), acts 2-3 give EVERY enemy one guaranteed gear item that suits its role (`guaranteed_gear`, `equipment_share` of it is equipment, else a finish; via `GearRules.pick`, never economy or player-only), act 3 adds one ENEMY RELIC (`enemy_relic_count`, pool `enemy_relic_pool`: Blast Cap, Home Field, Underdog, Bully, Grippy Table, Last One Standing, Opening Act; never economy). `RunManager.enemy_relics` is rolled in `_build_lineup`. `RelicEffect` has enemy-side hooks (`get_enemy_flick_power_multiplier(main, figure)`, `get_enemy_knockback_taken_multiplier(figure, source)`, `get_enemy_damping_multiplier()`, `get_enemy_explosion_radius_multiplier()`) that those 7 relics implement; the enemy flick power goes through `Figure.aura_flick_multiplier()` (so the AI and the real flick agree), damping in `main._spawn_figure`, knockback in `relic_knockback_taken`, explosions in `relic_explosion_multiplier(team)`. `Main.enemy_flicks_made` drives Opening Act. The relic is announced in the start-of-fight banner and as a red line under the top bar (`ui.show_enemy_relics`). Act 3 elites reward a choice of `relic_choices` (3) relics instead of one random relic (reward step `{kind: relics, elite: true, count}`).
- Elite AI tricks: Glue Gang (`EnemyAI.glue_chain_bonus` per extra player figure within `glue_chain_reach` of the target while the Glue Guy's chain cap allows), The Collector (hook `FigureAbility.wants_ally_food`: the Eater aims straight at smaller teammates and `eater_feed_bonus` cancels the ally-hit penalty), Powder Keg (existing `_blast_value`, Land Miner mine lines and Aggro-bom lines), Juice Bar (existing Bummer aura awareness), Siege (turret at combat start plus every enemy turn).
- Difficulty (only from Ascension 3, see above): `resources/difficulty_config.tres` (`DifficultyConfig`, per-act arrays): enemy `accuracy`, `flick_power`, `mass` multipliers ramp up a bit each act (regular enemies and, separately, bosses via `boss_*`); `scale_for(act, is_boss, is_elite)`. Applied in `Figure.setup(..., stat_scale, is_elite)` to a private copy of the FigureData (Slime pieces inherit the parent's `scale_factors`; Rewind keeps them via `base_data`).
- Boss fights always use `RunConfig.boss_arena` (Open Field: no walls, pins or patches; `RunManager._pick_arena()`).
- Enemy gear (only from Ascension 1; the rates are `AscensionConfig.gear`): `resources/enemy_gear_config.tres` (`EnemyGearConfig`, per-act arrays): act 1 none; act 2 each enemy 25% a general finish, 15% equipment; act 3 50% finish, 35% equipment, 10% a figure-specific upgrade (if its figure has one). Elites and bosses roll at the NEXT act's rates (`elite_boss_act_shift`). Rolled in `RunManager._roll_enemy_gear()` when the lineup is built (stored in `enemy_gear`, parallel to `enemies`), passed to `_spawn_figure` and drawn exactly like on player figures (badge, pip, glow...), kept by Rewind. Enemies never get `economy` or `player_only` equipment (`EquipmentData.player_only`: Coin Purse, Lucky Charm, Jet Pack). GEAR RULES (`scripts/gear_rules.gd`, data on the items under "Who it suits": `needs_ability_numbers`, `incompatible_abilities`, `role_weights`): `GearRules.fits()` rejects gear that would do nothing (Glow-in-the-dark needs an ability with scalable numbers, Wings not on Ghost, Magnet Charm not on Magnet, bounce bonuses not on figures that already bounce at 1.0), and `GearRules.pick()` weights by the figure's roles (`roles_for`: heavy, light, power, bouncy, slider, explosive), so Duwall gets Anchor/Boots/Helmet/Metallic and Powerhouse gets Spiked Helmet/Glitter. Figure-specific upgrades only come from `upgrades_for(figure)`. `tools/smoke_test.gd` checks the rules.

### Bosses

- `scripts/boss_data.gd` (`BossData`): name, description, map label/color, `back_wall` (a solid wall along the whole top edge of the table behind the boss, so it cannot be knocked off the back in one shot: ON for Slime, Skull-o-tron and Trangle, off for the others; `Arena.build(..., back_wall)` adds it to a private copy of the layout) and the `enemies` (FigureData list) for the fight. Each act draws its boss at random from its OWN pool (`FigureRegistry.bosses_act1/2/3`, `bosses_for_acts()`): act 1 The Wall or Sniper Squad, act 2 Trangle or Slime, act 3 Skull-o-tron or Mad Creator (`bosses` still lists all six); files `resources/figures/boss_*.tres`; boss stats scale up with the act (`DifficultyConfig.boss_*`). New `BossData` fields for the Mad Creator: `creator_box`, `summons` (4 figures), `box_wall_health`, `max_summons`. Map icons: `FigureIcons.Icon.TRIANGLE` and `BOX`, labels TR and MC.
- Boss stats live on the boss's figures in `resources/figures/`: mass, `accuracy`, `flick_power_multiplier`, and two FigureData fields: `can_flick` (false = the AI never flicks it) and `creep_distance` (slides that far straight toward the deck after every enemy turn; if its front edge reaches the deck line, the player loses; `board.show_deck_line` draws a faint dashed line there).
- The Wall (`boss_the_wall.tres`, `wall_piece.tres` x5, map label WL): five heavy pieces (radius 88, mass 6) in one straight row (`BossData.straight_row`) spanning the board from left edge to right edge. After every enemy turn ALL pieces creep toward the deck together by `creep_distance` (55) each, from wherever they currently are (knocked-back pieces keep creeping). If any piece's front edge reaches the deck line you lose; knock all 5 off to win. They don't flick by default: `can_flick` on `wall_piece.tres` is the toggle (turn it on and they flick like any enemy, with `no_repeat_enemy` rules). Sniper Squad (`sniper.tres` x5): small, light, accuracy 0.98, flick power 1.5 (`flick_power_multiplier` on `sniper.tres`).
- Skull-o-tron (`boss_skull_o_tron.tres`, `skull_o_tron.tres`, map label SK with its own SKULL icon via `BossData.map_icon`): ONE RigidBody (core radius 95, mass 14 before act scaling so it feels immovable at first, flick power 4.0 to compensate: the AI's top speed is force x power / mass, which gives typical moves of about 180px, `spawn_margin` 270 so the arms start on the board) with extra collision shapes added by `SkullotronAbility.setup_body()`: per arm a rectangle plus a ball circle (3 arms spaced evenly, `arm_length`, `arm_thickness`, `ball_radius` exports). It spins while it moves (`angular_velocity` = speed x `spin_per_speed` 0.017 capped by `max_spin` 9, zero when slow; the angle turned is spin_per_speed x distance, so a typical 180px move sweeps the arms about 160-180 degrees, measured; `lock_rotation` is off for it, `Figure._draw` counter-rotates the label), so the arms sweep and really hit figures. `Figure._on_body_shape_entered` finds which shape was hit and calls the new hook `FigureAbility.on_shape_hit(figure, other, shape_node, speed)`; a hit on an arm or ball at relative speed >= `break_speed` (650, @export; one arm per `break_cooldown_ms`) removes both shapes and `Figure.shed()` -> `shed_requested` -> `main._on_shed_requested()` spawns a Skull Ball (`skull_ball.tres`: radius 38, mass 0.7, average, enemy) (each unit adds an enemy flick, see Enemy flicks per turn). An arm JAMMED against a pin (arena pin or Pinhead pin, both in the `pins` group) while the body moves (>= `jam_min_speed` 40 px/s) for `jam_break_ms` (150) breaks off and releases its ball like a hard hit (`_check_jams`). With no arms left the core's mass is multiplied by `armless_mass_multiplier` (0.3). You win when the core and every Skull Ball are off the table. Other new body hooks: `setup_body(figure)`, `draw_body(figure)`. The AI treats it as its core circle (arm sweeps are not modelled). Open arena like every boss.
- Trangle (`boss_trangle.tres`, `trangle.tres`, `trangle_ability.gd`, act 2, map label TR): ONE heavy body (radius 120 for the AI, mass 8, flick power 2.8 to compensate) shaped like a triangle with concave sides: the ability's `setup_body` removes the circle and adds a `CollisionPolygon2D` (Godot splits the concave outline into convex pieces; `tip_distance` 135, `concavity` 0.85, `points_per_side` 8, all @export). On every flick it gets `flick_spin` (12 rad/s, random direction) that dies away with `spin_damp` and stops when it rests, so figures in its hollows are swept or flung. 2 flicks a turn (`BossData.enemy_flicks_per_turn`), existing shot evaluation (it is treated as a circle by the AI), open arena with the back wall (`back_wall = true`, so it cannot be knocked off the back in one shot). It draws itself (`FigureAbility.draws_own_body` hook makes `Figure._draw` skip the circle).
- Mad Creator (`boss_mad_creator.tres`, `mad_creator.tres`, act 3, map label MC): `CreatorBox` (`creator_box.gd`, built by main under the arena node when `BossData.creator_box`) puts a 480px box at the top of the table: 4 `BreakableWall`s (`breakable_wall.gd`, StaticBody on the arena layer, group `breakable_walls`, health `box_wall_health` 8000 = about 2 full-power Grunt hits, since one hit from the deck deals ~4200) around a floor with 4 colored spaces (Grunt, Speedo, Bumper, Powerhouse = `BossData.summons`) and the Creator (radius 60, mass 3, bounce 0.9, uneatable) in the middle. Damage uses Duwall's shell maths: a PLAYER figure's hit adds (1 + restitution) x its mass x closing speed (`Figure._on_body_entered`; the Creator's movement and its summons never damage the walls), an explosion adds force x falloff x `explosion_damage_scale` (3; `Figure.blast` calls `take_explosion` on every wall in range, whoever caused it). Cracks show at 1/3 and 2/3; at full damage the wall fades away. Enemy turn (2 flicks per turn): flick 1 is the Creator's (`main._creator_turn`): while it is inside the box it flicks itself in a random direction by `min_travel`-`max_travel` (150-520 px), and when everything settles the space nearest its center (`tile_index_at`) summons that figure in a free spot in front of the box (`free_spot_in_front`), a normal scaled enemy, unless `max_summons` (5) are already out; flick 2 is the usual AI flick among the summoned figures (the Creator is not a candidate while inside). Once it is outside the box it has no floor, no summon flick and flicks like a normal enemy. You win when the Creator is off the table: `_check_game_over` then removes every remaining summon.
- Slime (`boss_slime.tres`, act 2 pool): starts as one large slime (radius 100, mass 5). `SlimeAbility` (`scripts/abilities/slime_ability.gd`) splits it when `on_impact` speed >= `split_speed` (350; medium 300, lowered so it splits more easily) into `piece_count` (2) of the next size (medium: radius 70, mass 2.4, then small: radius 45, mass 0.9, which never split; lighter = easier to knock off), bursting sideways/away from the impact point at `burst_speed`. It works through `Figure.split_into()` -> signal `split_requested` -> `main._on_split_requested()`, which spawns the pieces as new enemies (they take their own turns from the next enemy turn) and retires the parent. The fight is won when every piece is off the table. Pieces ignore hits for `grace_ms` after birth. A split keeps only `inherit_velocity` (0.35) of the slime's post-hit speed, and fresh pieces take `fresh_knockback_multiplier` (0.5) knockback until the next round starts (`FigureAbility.on_round_ticked`, called from `Figure.tick_round()`), i.e. through the rest of that turn and the enemy's reply, so the hitter that plows on cannot one-shot them.

## Economy and shop

- Money lives on `RunManager` (`money`, `last_income`). When a normal combat is won, `main._end_game` calls `RunManager.award_income(figures_on_table)` (before `combat_won()`): `RunConfig.income_per_figure` ($1) per own figure still on the table (deck or board) plus each figure's `FigureData.income_bonus`. The reward screen shows `income_text()` (gold line under the title: "$X earned, you have $Y total"); the map shows "$N" top right. `RunConfig.starting_money` sets the start.
- Cha-ching (`cha_ching.tres`, CC, coin icon `COIN`): `income_bonus = 2` (paid when you win with it on the table) plus `ChaChingAbility`: +$1 (`knock_off_bonus`) each time an enemy is knocked off while it is on the table (`FigureAbility.on_opponent_knocked_off`, called by `main._knock_off_fallen_figures` on surviving player figures). Draftable.
- `FigureData.rarity` (0 Common, 1 Uncommon, 2 Rare) drives shop prices.
- Shops are map nodes (about 2 per act, 3rd row onward, one per row, see Run structure): optional, never a combat; each visit rolls fresh stock (`RunManager.enter_node` -> `config.shop.make_offers`). Leaving finishes the node.
- Config: `resources/shop_config.tres` (`ShopConfig`) holds `item_types: Array[ShopItemType]` and the prices (each type has its own exports); `make_offers(registry)` concatenates what each type's `create_offers()` returns (`ShopOffer`: title, description, price, optional figure, `needs_slot`, `slot_prompt`, `sold`, optional `blocked` callable returning a reason, `on_buy` Callable, `buy(slot)`). Types: `FigureForSaleType` (3 figures, price by rarity 3/5/8), `ReplaceServiceType` ($3 swap), `RelicsForSaleType` (price by rarity `price_by_rarity` $10/$12/$14, never Boss relics), `PowersForSaleType` ($4, needs a free slot), `EquipmentForSaleType` ($5), `UpgradesForSaleType` (ONE Upgrade at $20 for any upgradable figure, and a finish, $7, you pick the figure). To add a new kind: subclass `ShopItemType`, override `create_offers()`, add a sub-resource to `shop_config.tres`. `shop.gd` needs no change.
- Shop UI (`scenes/shop.tscn`, `shop.gd`, built on `ScreenFrame`): a scrolling list of `FigureCard`s (price in the text, disabled when sold/unaffordable/blocked), a fixed "Leave the shop" button; offers that need a figure go to a "which figure?" picker (the `DeckStrip`: tap a slot, then Confirm; Back button).

## Equipment

- Items attached to ONE figure for the run. `EquipmentData` (`scripts/equipment_data.gd`): name, 1-2 char `label` + `color` (drawn as a small badge on the figure's lower right), `economy` flag, plain stat changes (`mass_multiplier`, `bounce_bonus`, `damping_multiplier`, `income_bonus`) and an optional `effect`: ANY `FigureAbility` subclass (scripts in `scripts/equipment/`). Files: `resources/equipment/*.tres`; the whole catalog is `RunConfig.equipment_pool`. To add one: duplicate a `.tres` (and write an effect script if it needs hooks), add it to the pool.
- How it plugs in: `Figure.setup(..., item)` applies the stat changes, and if there is an effect it wraps the figure's own ability and the effect in a `CombinedAbility` (events go to both, multipliers multiply, the first `on_left_table` that saves the figure wins), so equipment uses the same hooks as abilities. Only player deck figures carry equipment (`main._spawn_players`, and Rewind's snapshot keeps it).
- New hooks on `FigureAbility` for this: `on_knocked_off(figure)` (not called when `knock_off(..., retired=true)`, e.g. a Splitter splitting), `get_hit_multiplier(figure, other, impact_speed)` (collisions only, not explosions), `get_flick_power_multiplier(figure)`, `get_incoming_aim_error_degrees(figure)` (EnemyAI adds it to the aim error of shots aimed at that figure), plus the helper `extra_hit_knockback(figure, other, bonus)`.
- Equipment has a `rarity` (0 Common, 1 Uncommon, 2 Rare; shown in the shop and reward text): Common Weighted Boots, Rubber Ring, Banana Peel, Mr Potential's Skull; Uncommon Spiked Helmet, Anchor, Magnet Charm, Short Fuse, Coin Purse, Lucky Charm; Rare Parachute, Jet Pack, Wings. Items: Mr Potential's Skull (`SkullEffect`, player-only: the figure takes 2x knockback from its own team while on the board; encounters can still force it onto an enemy via `EncounterEnemy.equipment`, e.g. The Setup's Grunt), Weighted Boots (mass x1.5), Rubber Ring (bounce +0.5), Spiked Helmet (+40% knockback dealt: adds 40% of the speed the victim gained), Banana Peel (damping x0.5), Parachute (once per combat, stops at the edge), Short Fuse (when its figure is knocked off it implodes: `Implosion` pulls figures within `implosion_radius` 300 toward the spot where it left the table for `implosion_seconds` 0.4, up to `implosion_strength` 1800 px/s per second at the spot, fading with distance), Magnet Charm (`MagnetCharmEffect extends MagnetAbility`, weak defaults), Anchor (ignores hits with impact speed < `impact_threshold` 500), Coin Purse (economy, +$1 at the end of a won combat via `award_income(figures, equipment_bonus)`), Jet Pack (extra half-power flick per combat, offered after the normal flick like Speedo; tap to skip without spending it), Wings (once per combat Ghost-style wrap), Lucky Charm (+15 deg aim error for shots at it).
- Storage in `RunManager`: `deck_equipment` (parallel to `deck`, null = none), `equipment_inventory` (items held but unequipped), `equip(item, slot)` (the old item of that figure goes back to the inventory), `add_equipment()`. `replace_figure()` returns the old figure's item to the inventory (reward, shop figures and the swap service all use it). `RunConfig.start_with_equipment` (@export testing toggle, OFF by default) + `starting_equipment_count` (2) put random items in the inventory at the start of a run. Treasure nodes and the shop hand out equipment (`add_equipment()`).
- Equip screen: `scenes/equip.tscn` / `scripts/equip.gd` (no longer linked from the map: equipping is done in the top bar's Inventory).

## Powers

- One-time-use items the player holds and uses during combat. `PowerData` (`scripts/power_data.gd`: name, description, button color, `effect`) + a `PowerEffect` subclass (`scripts/powers/*_effect.gd`). Files: `resources/powers/*.tres`; every power in the game is listed in `RunConfig.power_pool`. To add one: write a `PowerEffect` subclass (set `target_mode` and optionally `settle_after`/`prompt` in `_init()`, override `can_use(main)` and `apply(main, targets) -> bool`; return false to keep the power), duplicate a power `.tres`, add it to `power_pool`.
- `PowerEffect.Target`: NONE (instant), ENEMY, OWN_FIGURE, TWO_FIGURES, POINT (a tap on the board; `targets` is `[Vector2]`). `settle_after = true` makes main wait for the board to settle afterwards (Bomb Drop, Earthquake, Swap).
- Storage: `RunManager.powers` (`Array[PowerData]`, `RunConfig.power_slots` = 3 slots, null = empty) persists across combats until used; `add_power()`, `use_power(slot)`. `RunConfig.start_with_powers` (@export testing toggle, OFF by default) and `starting_power_count` (2) give random powers at the start of a run.
- UI: `PowerBar` (HBox of 3 buttons, built by `ui.set_powers()`) in the bottom bar below the turn label; grey and inert unless it is the player's turn. Main ignores taps over the bar (`ui.is_over_power_bar`). Tap a power: instant ones fire; targeted ones show a prompt and wait for a tap (tap the same button to cancel). Using a power never uses up the flick (state stays PLAYER_TURN, or SETTLING then back via `_resume_player_turn()`).
- "A round" = from the moment of use until the start of the player's next turn: `Figure.tick_round()` and `arena.tick_round()` run in `_start_player_turn(new_round)` (Extra Turn flicks pass false so they don't advance rounds). Freeze Ray (`freeze_for()`: static body, excluded from `_flick_candidates` and creeping), Bubble Shield (`bubble_rounds`: `_stop_at_edge()` in `_knock_off_fallen_figures` clamps it to the table instead of knocking off), Brick (`arena.add_brick()`, 2 rounds, refuses if a figure is in the way), Magnet Throw (`arena.add_magnet_zone()`, 1 round, same pull curve as the Magnet figure; `field_radius` @export on the effect, 225).
- The others: Super Flick (`main.flick_boost` x3, consumed by the next flick, shown in the status line), Rewind (a snapshot of every figure is taken right before each player flick; `rewind()` replaces all figures with fresh copies, so knocked-off ones come back and per-figure ability state restarts; it also restores the boost, extra turns and enemy flick count), Swap (positions, and `on_deck` follows the position), Bomb Drop (`Figure.blast()` static + `BlastEffect` ring), Earthquake (`nudge()` everyone), Extra Turn (`main.extra_turns`: after the next flick settles you flick again before the enemy acts), Glue Puddle (`arena.add_glue_puddle()`: stops figures as they ENTER, so one flicked from inside still leaves; `rounds` 0 = rest of the combat), Shrink Ray (`Figure.shrink()`: half size and mass, once per enemy).
- Power-placed bricks/zones live in the `Arena` node (`_bricks`, `_zones`, drawn by `ZoneVisual`). Powers come from elite rewards (chance), Clean Sheet and the shop (`RunManager.add_power()`).

## Figure upgrades (toy finishes)

- Each deck figure can have ONE general finish (`FinishData`, any figure) and an UPGRADE TREE (below). Per deck slot `RunManager` stores `deck_finish` and `deck_upgrade` (a `Vector2i(path, tier)`: path -1 none, 0 = A, 1 = B; tier 0-3; `RunManager.NO_UPGRADE`), parallel to `deck`; replacing a figure removes both. Pools: `RunConfig.finish_pool` and `RunConfig.upgrade_trees`.
- `FinishData` (`scripts/finish_data.gd`): `look` (SPARKLE, SHEEN, GLOW, TRANSLUCENT, RUBBER; drawn by `Figure._draw_finish()`, animated through `_process`), tint color, plain changes (`mass_multiplier`, `knockback_taken_multiplier`, `ability_strength`) and an optional `effect` (any FigureAbility, scripts in `scripts/finishes/`). Finishes: Glitter (+25% knockback dealt, via `extra_hit_knockback`), Metallic (mass x1.5, takes 25% less knockback), Glow-in-the-dark (`ability_strength` 1.5 multiplies the ability numbers listed in `Figure.STRENGTH_PROPERTIES`: explosion_radius, pull_radius, pull_acceleration, bounce_boost, bump_ratio, nudge_speed), Translucent (alpha 0.55; collision exceptions with all allies for a flick until it touches the first one, then every other ally collides again), Rubber (new hook `on_hit_wall(figure, body)`: x1.5 speed after bouncing off a wall or pin; plain `bounce` can't do this because Godot caps summed bounce at 1 and walls are already ~1).
- UPGRADE TREES: `UpgradeTree` (`scripts/upgrade_tree.gd`: `figure`, `path_a_name`, `path_b_name`, `path_a` / `path_b` = 3 `UpgradeData` each; files `resources/upgrades/<figure>/tree.tres` + `a1..a3.tres`, `b1..b3.tres`, one tree for every draftable figure, 180 upgrades) and `UpgradeData` (`scripts/upgrade_data.gd`: `display_name`, `description`, `data_overrides` / `data_multipliers` on the figure's FigureData copy, `ability_overrides` / `ability_multipliers` on its own ability copy (applied in order, tier 1 first; multipliers compound), optional `extra_effect` (any FigureAbility), `run_modifiers` (e.g. `shop_discount`, summed over the deck by `RunManager.run_modifier`)). Rules: tiers in order; the first pick chooses the path and locks the other. API in `RunManager`: `tree_for(figure)`, `owned_upgrades(figure, state)`, `upgrade_boxes(figure, state)` (owned / available / locked per box), `can_upgrade(slot)`, `upgradable_slots()`, `take_upgrade(slot, path)`, `next_tier(slot, path)`, `upgrade_summary(slot)`. `Figure.setup(..., upgrades: Array)` applies them (`Figure.upgrades`, `Figure.upgrade_state` for Rewind); `Main._spawn_figure(..., upgrade_state)` resolves the state. To change a number or text just edit the `.tres`; most effects are new `@export`s on the figure's ability (named in the upgrade's `ability_overrides`). UI: `UpgradeTreeView` (`scripts/upgrade_tree_view.gd`: two rows of three boxes, tap for the description) in the reward Upgrade step (`reward.gd` `_show_upgrade` / `_show_upgrade_tree`; step `{kind: upgrade, slot?}`), the Inventory figure details and the Compendium figure page; gold pips on figures (`Figure._draw`) and on the deck strip (`FigureBadge.upgraded` = tiers owned). Sources (numbers in `RewardConfig` / `ShopConfig`): elites `elite_upgrades` 1, bosses `boss_finishes` 1 + `boss_upgrades` 1, regular combats never (`bonus_item_kinds` is power / equipment), shop `UpgradesForSaleType` (ONE Upgrade offer, `upgrade_price` $20, `ShopOffer.is_upgrade`: pick any upgradable figure, then a tree box), the Trader's high trade (`EventScreen.follow_up_steps` sends an Upgrade step through the reward screen). Enemies: `_roll_enemy_upgrade` (Ascension 5 Upgraded Enemies: tier 1 on one path, elites/bosses' figures up to tier 2; gear rolls no upgrades); `EncounterEnemy.upgrade_path` / `upgrade_tier`; Mirror Match copies `deck_upgrade`. Saves store `deck_upgrade_state` as [path, tier]; `RunSave.OLD_UPGRADES` migrates the old single upgrades. NEW GENERAL HOOKS used by the upgrades: `get_dealt_knockback_bonus(figure, other)` (applied by `Figure._apply_dealt_bonus`, also `Figure.temp_dealt`), `get_enemy_aura(figure)` ({radius, knockback, flick}: Crazy Man Frenzy, Bummer Downer; `Figure.enemy_aura_factor`), tap abilities (`get_tap_ability` / `use_tap_ability`: kind "self" = tap the selected figure again, even one that already went; kind "point" = tap empty board; `Main._try_self_tap`, `_after_tap_ability`; the AI uses `ai_wants_tap` / `ai_tap_point` at the start of the enemy turn in `Main._enemy_tap_abilities`), `get_reward_choice_bonus`, `on_projectile_hit`, `get_stuck_enemy_flick_multiplier`, `get_team_explosion_reduction`, `get_pin_options`, `Main.grant_bonus_flick(figure)` (a queued extra flick), `Figure.can_act_now()`, and Figure fields `temp_dealt` / `temp_taken` (cleared at the owner side's next turn), `charge_power`, `shock_flick`, `doused_flick`, `stunned_rounds`, `bummed_extra`.
- Applied in `Figure.setup(..., equipment, finish, upgrades)`: data copy, mass, ability overrides, glow scaling, then equipment / upgrade / finish effects combined with `CombinedAbility`. A figure with upgrades shows one small gold pip per tier in its upper right.
- The shop (`UpgradesForSaleType`) sells Upgrades and finishes; bosses and elites hand them out through reward steps (see UPGRADE TREES). The old testing-only Upgrades screen and `RunConfig.show_upgrade_screen` were removed.

## Relics

- Passive run-wide effects. `RelicData` (`scripts/relic_data.gd`: name, 1-2 char `label`, description, `color`, `economy` flag, `effect`) + a `RelicEffect` subclass (`scripts/relics/*_effect.gd`, base `relic_effect.gd` with no-op hooks). Files: `resources/relics/*.tres`; the whole catalog is `RunConfig.relic_pool`. To add one: write an effect overriding the hooks it needs, duplicate a `.tres`, add it to the pool. Effects are shared resources, so keep per-combat state on Main (like `main.second_wind_used`), not on the effect.
- Storage: `RunManager.relics` (`add_relic()` rejects duplicates and calls `effect.on_acquired(run)`; `random_new_relic()` only returns relics not yet held). `RunConfig.start_with_relics` (@export testing toggle, OFF by default) + `starting_relic_count` (3). RARITY: `RelicData.rarity` (COMMON, UNCOMMON, RARE, BOSS; `rarity_color()`/`rarity_name()`; the relic icons in `RelicBar` get a border in that color). Common: Grippy Table, Lucky Coin, Aim Assist, Home Field. Uncommon: Bully, Underdog, Gravity Well, Trophy Case, Clean Sheet, Blast Cap. Rare: Last One Standing, Opening Act, Starter Walls. Boss: Extra Pocket, Second Wind. Common also: Costume Change. `RunManager.random_new_relics(n)` (chests, elites, shop) rolls the rarity with `RewardConfig.relic_weights` (0.65/0.30/0.05 common/uncommon/rare) and never gives Boss relics; `random_boss_relics(n)` (boss reward) draws Boss and Rare relics first. `RunManager.combat` is the Main node during a combat (set in `main._ready`, cleared in `_exit_tree`) so effects can read the board and counts (`main.get_player_count()`, `get_enemy_count()`, `player_flicks`, `board`).
- Hooks (RunManager asks every held relic): `get_explosion_radius_multiplier` (all explosions, both sides: `Figure.explode`, Bomb Drop), `get_flick_power_multiplier(main, figure)` (in `_flick_impulse`, so the aim line agrees), `get_player_damping_multiplier` (player figures only, in `_spawn_figure`), `get_knockback_taken_multiplier(figure, source)` (collisions and `take_knockback`), `get_pull_multiplier` (MagnetAbility and Magnet Throw zones), `enables_reload`, `shows_aim_bounce` (`main._predict_bounce()` shape-casts the shot and AimLine draws a second dotted leg), `on_player_figure_falling(main, figure)` (return true to save it; checked after Ghost/Parachute), `get_income_bonus` (`award_income`), `get_reward_choice_bonus` (`offer_rewards`; reward cards shrink to fit), `on_combat_won(run, info)` (returns a note shown under the earned line; `info.figures_lost` counts player figures knocked off for good, so Second Wind returns don't count).
- Costume Change (Common, `costume_change_effect.gd`, hook `RelicEffect.enables_combat_equip`): `RunManager.equipment_change_allowed()` is true outside combat, and in combat only with this relic while `Main.can_swap_equipment()` (PLAYER_TURN, no bonus flick pending). The Inventory then allows equip, unequip and swap in combat (reordering stays locked) and calls `Main.refresh_equipment(slot)` -> `Figure.set_equipment(item)` (mass, damping, bounce and the equipment effect are re-applied live; `Figure._core_ability` + `_equipment/_upgrade/_finish_effect` are re-combined by `_rebuild_ability`). No flick is used.
- Relics: Starter Walls (Rare, `starter_walls_effect.gd`, hook `RelicEffect.on_first_enemy_turn(main) -> wait seconds`, asked through `RunManager.relic_first_enemy_turn`): in `main._run_enemy_turn`, on the first enemy turn of a combat (`_enemy_turns_taken` == 0), after the turret placement and before the first shot, a `ShieldWall` (Shieldon Ooper's wall class, 190 x 26, `wall_gap` 10, all @export on the effect) pops up (`ShieldWall.pop_up()`, only the picture animates; the collision is there at once) above every player figure that is still unflicked on the deck (`Arena.place_starter_wall`, sharing `_make_shield_wall` with Shieldon; skipped if something is in the way), the enemy waits `pop_wait` (0.45 s), and `main._start_player_turn` removes them (`Arena.remove_starter_walls`). They are real arena-layer bodies, so the AI's shape casts already treat them as walls. Blast Cap (x1.5), Opening Act (first flick of a combat x2), Extra Pocket (`add_deck_slot()`), Aim Assist, Grippy Table (damping x1/0.7 = 30% shorter slides), Home Field (half knockback in the bottom third of the board), Bully (2x knockback to enemies within 200px of the table edge when hit by your figures), Underdog (x1.5 flick power while you have fewer figures than the enemy), Last One Standing (x2 power, half knockback when you have one figure), Second Wind (first knocked-off figure each combat returns to its deck slot), Lucky Coin (economy, +$1 per won combat), Trophy Case (+1 reward choice), Gravity Well (pulls x2), Clean Sheet (random power if no figure lost; message says if slots are full).
- UI: relics are shown in the Inventory's Relics tab (the old `RelicBar` icon row is gone). Relics come from elite rewards, treasure nodes, boss rewards (pick 1 of 3) and the shop.

## Game feel

- `scripts/game_feel.gd` (GameFeel node, with a Camera2D child used for screen shake) holds all the "juice": squash/stretch, impact particles, screen shake, knock-off pop, and haptics (`Input.vibrate_handheld`, mobile only). Each effect has an `@export` bool switch on that node; all other numbers are exports too.
- Figures only emit signals (`flicked`, `impacted`, `fell_off`); `main.gd` connects them to GameFeel when spawning. Impact speed is the relative speed just before the collision. Squash/pop are drawn in `Figure._draw` (the RigidBody is never scaled).
- Haptics need the Android Vibrate permission, which is already ticked in the committed `export_presets.cfg`.

## Main menu and run saving

- Main scene = `scenes/main_menu.tscn` (`scripts/main_menu.gd`, built in code, placeholder styling, title "Flick Figures"): Continue (only with a saved run), New Run (asks "Start a new run? Your saved run will be lost." first when a save exists), Compendium and Run History (their own scenes, see below), Settings (game-sound and menu-sound sliders, mute: they call `AudioManager`). Winning the last act or losing returns to the menu (tap), no longer straight into a new run. `NodeScenes` (`scripts/node_scenes.gd`) holds the scene paths and `open_current_node()` (used by the map and by Continue).
- Saving (`scripts/run_save.gd`, `RunSave`; file `user://run_save.json`, JSON): `RunManager.autosave()` runs every time the map screen opens (`map._ready`; it does nothing while a node is being played). It stores seed, act, act bosses, the act's map (nodes, links, types, visited), current node, money, minigame penalty / harder-fight flags, `first_combat_played`, deck with finish / upgrade / equipment per slot, unequipped equipment, relics, powers, used encounters and events and the last arena, all by resource path (a figure that no longer exists becomes the starting figure). Relics are put back directly (no `on_acquired` again).
- Quitting inside a node: `RunManager.enter_node()` writes `pending_node` into the save (`RunSave.set_pending`) and seeds the RNG from (seed, act, node id), so Continue calls `enter_node(pending)` again and gets the SAME lineup / arena / shop stock / event from the start. Combat state itself is not saved; powers used or money spent in that node are not kept. Rewards are not saved either: quitting on the reward screen replays the combat. The act maps are generated from `hash([run_seed, act])`.
- The save is deleted when the run ends (`RunManager.end_run()` from `main._end_game` on a loss or the final win) and when New Run starts. The Inventory screen has a "Main menu" button: it autosaves when you are on the map (outside a node), otherwise the existing save (which remembers the node) stays, then goes to the menu.

## Run history, stats and Compendium

- `RunHistory` (`scripts/run_history.gd`, static, file `user://run_history.json`, kept across sessions and NOT deleted with a run save): `runs` (one entry per finished run) and `seen` (figure paths the player has met). `RunManager.end_run(won)` (called from `main._end_game` on a loss or the final win) calls `RunHistory.record_run`: date, won, act reached (1-based) and `acts`, node text ("Combat, stop 3" / "Boss"), the boss that ended a lost run (only when it was a boss node), final deck (figure, finish, upgrade, equipment per slot), relic names and every figure picked (`RunManager.picked_figures`, appended in `replace_figure`, so drafts, shop buys, swaps and trades all count; saved in the run save too). Quitting to the menu without finishing records nothing.
- Stats (`RunHistory.overall_stats()`, `figure_stats()`, `ranked_figures("picked" | "win_rate")`, `stats_for(figure)`): runs, wins, win rate, furthest act; per figure: times picked, runs where it was in the final deck (once per run) and the win rate of those runs (-1 = never in a final deck; sorted last).
- Unlocking: `RunHistory.mark_seen(figure)` is called when a figure is offered (`draft_figures`, `offer_rewards`, the Trader's offers), owned (starting deck, `replace_figure`, loading a save) or faced (`enter_node` marks the combat's `enemies`). The Compendium lists the Grunt and every draftable figure.
- Screens (both extend `MenuScreen`, `scripts/menu_screen.gd`: dark background, title, scrolling `content`, bottom `actions`, no top bar): `scenes/run_history.tscn` (`run_history_screen.gd`: stats block with a Most picked / Win rate toggle showing the top 5 (Show all), then the runs newest first; tap a run to expand its deck, relics and picks) and `scenes/compendium.tscn` (`compendium.gd`: 3-column grids grouped Common / Uncommon / Rare, sorted by name; locked = dark silhouette with "???" and not tappable; tap an unlocked figure for its `FigurePage`). `FigurePage` (`figure_page.gd`): picture (`FigureBadge`, also used for the grid), name and rarity, the `FigureInspector`, ability description, mass / flick power / knockback taken / bounce, its figure-specific upgrade(s) (`RunManager.upgrades_for`) and the player's own stats.
- 3D viewer slot: `FigureInspector` (`figure_inspector.gd`) is the clearly marked empty box on the page ("3D MODEL VIEWER (coming soon)"). To add the viewer, keep the class and `show_figure(data)` and replace `_build_placeholder()` with a SubViewportContainer holding a Node3D scene; no other file needs to change.

## Audio

- `AudioManager` autoload (`scripts/audio_manager.gd`, no `class_name`): every sound goes through it. Sound FILES are plain placeholders in `audio/sfx/` (`clack_plastic`, `clack_wall`, `boom`, `implosion`, `fall_pop`, `flick`) and `audio/ui/` (`tap`, `confirm`, `back`, `purchase`, `reveal`, `fanfare`), made by `tools/generate_sounds.py` (numpy; synthesized because no sound packs can be downloaded here). To use real sounds replace a .wav with the same name (and do not re-run the script, it overwrites them); a missing file just plays nothing. The `.wav.import` files are committed like `icon.svg.import`.
- Hooks (all direct calls): `Figure._on_body_entered` (figure clack, scaled by impact speed, and wall/pin clack with `_last_velocity`), `Figure.launch`/`shoot_at` (flick), `Figure.blast` (boom scaled by radius; Bombo, Blastoid, Land Miner, Bomb Drop...), `Implosion._ready`, `Figure.knock_off` (fall pop, not for retired figures), `main._end_game` (fanfare on a win), `reward._next_step` (reveal), `shop._buy` (purchase). Every `BaseButton` in the game gets a tap / back / confirm sound automatically (`node_added`; picked from the button text: "back/leave/close/skip/cancel/discard/no" = back, "done/confirm/continue/ok/take/start/yes/accept" = confirm, else tap). An explicit `play_*` call in the same frame replaces the automatic one; add a button to group `no_ui_sound` to opt out.
- Clacks: volume and pitch scale with impact speed (`clack_min_speed`/`clack_max_speed`, `clack_quiet_db`/`clack_loud_db`, `clack_pitch_low`/`clack_pitch_high`) with a random pitch wobble (`pitch_variation`), and a throttle (`clack_gap_ms`, `wall_gap_ms`, `boom_gap_ms`: a sound inside the gap is skipped unless clearly louder than the last one). All @exports on the autoload.
- Buses `SFX` and `UI` are created at startup, each with its own volume (`sfx_volume`, `ui_volume`, 0-1) and a shared `muted` flag; saved in `user://audio.cfg`. The TopBar has a small SND/OFF button (`toggle_mute()`); there is no volume slider UI yet (`set_sfx_volume()` / `set_ui_volume()` exist).

## Builds

- `.github/workflows/build.yml` runs on every push to `main`: it exports an Android APK (debug-signed with the committed, public `signing/debug.keystore`, so new builds install over old ones) and a web build, then republishes them on the GitHub release tagged `latest` ("Latest build"). `export_presets.cfg` is committed (Android + Web presets, no secrets). See `BUILDING.md` for how to install and share. The renderer is GL Compatibility (needed for web, and the safest on phones).
- A real release keystore (for Google Play) must go in GitHub secrets, never in the repo.
- WEB / IPHONE: the same workflow deploys the web export to GitHub Pages (job `pages`, stable URL https://codercroft.github.io/Flick-Figures/; needs Settings > Pages > Source: GitHub Actions once). The Web export preset uses the custom page template `web/shell.html` (`html/custom_html_shell`; `web/` has a `.gdignore` and `exclude_filter="web/*"` so it stays out of the editor and the pack): viewport-fit=cover, apple-mobile-web-app meta tags (standalone, black-translucent status bar, theme color), `manifest.webmanifest` (standalone, portrait) and PNG icons rendered from `web/icon-source.svg`, no scrolling or bounce, a "turn your phone upright" overlay in landscape, and a `screen.orientation.lock` attempt. The CI step "Prepare the web build" renames `index.*` to `index-<run number>.*` (cache busting), patches the references and `__BUILD__` in `index.html`, and writes `version.json`; at start the page fetches `version.json` (no-store) and reloads once onto a newer build, and while playing it polls (every 60 s and on returning to the tab) and shows a tap-to-update bar instead of reloading mid-run. Safe areas on the web: the page measures CSS `env(safe-area-inset-*)` (`window.flickSafeInsets()`, in game units) and `SafeArea.insets()` reads it through `JavaScriptBridge` (cached 0.5 s). Haptics: `GameFeel._vibrate` only calls `Input.vibrate_handheld` on the web when `navigator.vibrate` exists (never on iPhone), so nothing errors. Web is single-threaded (`thread_support=false`), so no special headers are needed.

## Project settings

- Viewport 1080x1920, portrait, stretch mode `canvas_items`, aspect `keep_width`.
- `input_devices/pointing/emulate_touch_from_mouse` is enabled so the game can be tested with a mouse on a laptop. Write input handling against touch events (`InputEventScreenTouch` / `InputEventScreenDrag`), not mouse events.

## Code style

- Descriptions (figures, relics, powers, equipment, finishes, upgrades) must be short (one line where possible) and match what the code does. Re-check them whenever behavior changes.

- The developer is learning Godot/GDScript and will tweak game feel a lot.
- Prefer simple, readable code over clever or abstract code.
- Expose every tunable value (flick strength, friction, mass, bounce, turn timings, etc.) as an `@export` variable, with a sensible default and a short comment, so it can be adjusted in the Inspector.
- Use static typing where it helps readability, and keep scripts small and focused.

## Bonus flicks

- ALL extra flicks go through `Main._offer_bonus_flick(figure)` (Speedo, Bloodluster, Jet Pack, `grant_bonus_flick` queue, Rewind re-offer). It must set `figure.flickable = true` because `launch()` clears it and the aim guards reject non-flickable figures. The UI shows "Bonus flick! ..." and `ui.skip_button` (signal `bonus_skipped` -> `_skip_bonus_flick`). After changing the turn state machine or any flick hook, run `godot --headless -s tools/bonus_flick_test.gd` (scripted real combats; exit 1 on failure).

## Sandbox

- Main menu > Sandbox (`SandboxSetup.begin()`): the real combat scene with `SandboxSetup.active`. ## Ascension levels

- The level list is DATA: `AscensionConfig.level_names` / `level_descriptions` (`max_level` is derived from them, no hard cap anywhere: selector, `AscensionProgress`, top bar, run history and per-level stats follow). Code never tests a literal level: use `asc(config.ascension.level_xxx)` (the "Level numbers" exports). To insert a level, add its name + description in the right place, shift the `level_*` numbers after it, bump `AscensionProgress.VERSION` and add a migration (`migrate_level`, `FIRST_SHIFTED_LEVEL`) for saves and history (`RunHistory.LEGACY_NAMES`). Enemy upgrades: `RunManager._roll_enemy_upgrade` (level_upgraded, chances in `AscensionConfig`); gear (finish/equipment) is separate (`_roll_enemy_gear`). Test: `tools/ascension_test.gd`.

## Spray / toss windows

- Besides bonus flicks, `Main._offer_bonus_flick(figure, mode)` also offers a `"spray"` window (a Spitter that flicked this turn may still spray, holding as before; sharing its water) and a `"toss"` window (a Cluster that tossed may toss again, tapping the board; never the last clustling). The hook `FigureAbility.wants_post_action(figure)` ("spray" / "toss" / "", called once per offer from `_finish_player_turn`) decides; `Main._bonus_mode` makes `_release_aim` ignore flicks in these windows and the Skip button ("Done spraying" / "Done tossing") ends the turn. Enemies do not use them yet. Test: `tools/balance_test.gd`.
